## What is drawn (left → right, top → bottom)

**1. The arena, with an agent in it (top-left).** A blue circle; a red stick
figure labelled `agent` inside it. The primitive of the whole board: an agent is
always *in* an arena.

**2. Human agency flows in (below it).** `human agency (CHOICE) flows into
virtual arena through virtual agent`. Red on "human agency (CHOICE)" and
"virtual agent"; blue on "virtual arena".

**3. The three interface examples (middle-top), each a pair.** Labelled down
the right edge as **one continuous pattern** (a long arrow running down):
- `text` (blue) ←→ `cursor` (red): a text field `abcd|efg` with the caret red.
- `GUI` (blue) ←→ `mouse` (red): a window of icons with a red pointer.
- `game` (blue) ←→ `avatar` (red): a stick-figure-to-avatar arrow.

The pattern: **blue = the arena, red = the agent's extension into it.** Text has
a cursor; a GUI has a mouse; a game has an avatar. Same relation, three scales.

**4. The equations (top-right).**
- `selection = attention = animation` (with **attention** underlined in red)
- `ensoulment` — drawn as a red starburst/scribble: energy radiating from a
  small dense centre
- `surface area of interaction` (blue/red)
- `selection = soul extension`

**5. The arrow's landing (centre-bottom): the physical arena.** A blue circle
containing: a human figure (red) at a laptop; the laptop's screen holds a
*smaller* blue circle with `arena` + a red `agent` inside it; dotted red sight
lines run from the human's eye to the screen; the same red starburst
(ensoulment) sits on the human; `input` labels the keyboard/mouse. **The
recursion: the physical arena contains a human agent who contains, on the
screen, a virtual arena containing a virtual agent.**

**6. The interface inventory (right).**
`physical interface` — `inputs` (blue) ←→ `outputs` (red):
`camera ←→ screen` (video) · `mic ←→ speaker` (audio) · `mouse`, `keyboard`
←→ `motor`. Then `digital interface`.

**7. The conclusion (bottom-left).**
`macOS already = infinite game engine` · `DreamOS makes it explicit` (DreamOS in
large red).

## The spine (what the DreamSong must carry)

1. An agent is in an arena. (the primitive)
2. Human choice flows into a virtual arena *through* a virtual agent.
3. That relation is ONE continuous pattern at three scales: cursor in text,
   mouse in GUI, avatar in game.
4. Selection = attention = animation = soul extension. Ensoulment is the human
   pouring agency down the interface into the virtual agent.
5. Zoom out: the physical world is itself an arena, containing us, containing a
   screen, containing another arena. The interface is the membrane — inputs and
   outputs paired (camera/screen, mic/speaker, keyboard/motor).
6. Therefore macOS is *already* an infinite game engine; DreamOS makes it
   explicit. DreamTalk generalizing to all UI = the surface area of DreamOS.

## Notes for the loop (this is the point)

- The drawing's **colour convention is load-bearing** and it matches DreamTalk's
  canonical palette already: **blue = arena/container/system**, **red =
  agent/attention/soul**. Read colour, not just shape.
- Spatial layout on a whiteboard encodes *sequence* loosely (left→right,
  top→bottom) and *grouping* tightly (things near each other belong together).
  The long arrow down the middle was David drawing the sequence explicitly —
  look for such connectors; they are the storyboard.
- Repeated glyphs (the arena circle appears 3×, the starburst 2×) are the
  **recurring symbols** — the holonic recognizer's job: create it once, reuse it.
  Here: `Arena`, `AgentFigure`, `Ensoulment` are the reusable holons.
- Text on the board is mostly *labels for drawings*, not content. Only the
  equations and the two conclusions are text that must appear as text.
