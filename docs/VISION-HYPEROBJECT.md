## The turn

Not "make a DreamSong for the InterBrain release video", but **build a
coherent hyperobject**: a high-dimensional visual state machine whose
symbols you can interact with. What gets rendered and uploaded to YouTube
is just **one song line** through it — a path defined programmatically
through the state space.

- **Where does the song end and the app begin?** Nowhere: it is one thing,
  a high-dimensional state machine ("3D first"). The release video is both
  a recording of the living app and something unfolding out of the song.
- **Which comes first in the UX-first cycle?** The experience. The code is
  then organised along the hyperobject of the InterBrain.
- The precedent David names: HyperCard — click a button, the visual state
  updates; a visual state machine.

## DreamTalk ↔ DreamSong: each contains the other

- A DreamSong is woven from DreamTalk symbols; a DreamTalk symbol contains
  many DreamSongs, at least in potential. Reflexive.
- Made rigorous: **the DreamSongs held in a DreamNode are linear sequences
  through subspaces of its visual state machine's phase space.** Dream
  weaving is still linear storylines forming constellations, but all of it
  lives inside the space of every possible state of the "app".
- Until now the InterBrain related symbol and songs as a disc: the symbol
  on the front, one or more songs on the back — a conceptual pairing. Now
  front and back share **one state-machine graph**, and the symbol is its
  entry point.

## The symbol unfolds into the UI

- Opening InterBrain: its DreamTalk symbol — the flower-of-life sphere with
  the obsidian crystals and the Project Liminality logo — and once you have
  friends, they and the ideas you hold with them show up *in* that symbol.
  The symbol unfolds into the DreamSong that *is* using the InterBrain.
- Against iOS: an icon's zoom-and-fade says only "these are equivalent";
  a flip already says "front and back of one thing". DreamTalk can
  *qualify* the relationship: the symbol unpacks into the UI in a
  semantically meaningful transition. You are always interacting with the
  one hyperobject. Like iOS icons that read out live state (calendar,
  clock), the small symbol shows what is inside.
- Improve a symbol's style once and quality rises everywhere — a software
  module for the visual side; the depth of interactivity underneath can
  evolve the same way.

## One repo: app, song, tutorial, docs, roadmap

- One seamless state space with islands: the everyday app UX, the
  first-use tutorial, the explanatory DreamSongs, and the rendered song on
  YouTube. Everything belonging to the vision is part of the evolving
  state machine.
- The song lives in the same repo as the app: **instead of a README, a
  WatchMe** — a high-dimensional README. In future a human writes the
  README "the right way" and AI does the rest.
- Deduplicate the app's visual components with the DreamTalk symbols (the
  DreamNode symbol in the app and in the song about the app, which is part
  of the app); update the symbols where required.
- READMEs become nested DreamSongs, subspaces of the machine: pause the
  explaining song, unpack e.g. the CoherenceBeacon, go as deep as you like,
  then return and continue the choreography.
- The reverse-engineered pitch gives the basic DreamOS front-end structure
  (the holons); fused with the main repository, the process should be
  self-defining — it contains its own context. New features and decisions
  update the song; the song describes what has not happened yet; close the
  gaps in both directions, nested into one fractal structure.
- **The roadmap is part of the hyperobject**: the discrepancy between the
  implementation and what the song describes is itself a subspace you can
  trigger, a symbolic interface into the remaining work. With proactive
  agents, you develop the vision and the agents implement and keep
  rewriting it, growing with the compute available.

## The state-space lattice

A parametric symbol that takes **any** object and visualises the state
machine underneath as a 3D lattice, with its regions (tutorial, the
explanatory song, the app's own functionality) — showing how several
DreamSongs specified through one machine fit together. Not mocked data:
shown on the InterBrain itself. Visualise how weaving machines into larger
machines makes the phase space explode: fractal, holonic state machines,
richer phase spaces for richer symbols.

## Description implies the system

- "The description of the system is the system" — more precisely, it
  *implies* the system. The laziest, most effective use of superintelligence
  is to boil things down to one artifact that holds all the implications
  for AI to actualise. A DreamSong is a catalyst that actualises the
  potential latent in available compute; its fractal structure holds the
  high-level clarity and the low-level precision in one state machine, with
  explanation and feature living together and co-evolving, modularly.
- Every symbol its own agentic layer; every DreamNode an agent. Scene
  graph, compute graph, the symbolic and its execution: one thing.
- **DreamOS has to manifest in explaining how it works** (another strange
  loop). When it can be fully explained, it works.
- DreamTalk + InterBrain synthesise into the specification that is DreamOS
  (AURYN is what makes the InterBrain agentic); the DreamOS DreamSong
  imports both hyperobjects. Building the DreamOS song entails building the
  other two. Later songs import it (Symbiotic Convergence imports DreamOS).
  The order of songs need not be decided yet.
- The AURYN DreamSong is on the list: start simply with what is already
  known, as individual visualisations sharing one symbolic base.
- The development process: David explains aspects in words and on the
  whiteboard; they are translated into a deduplicated digital structure;
  emerging scenes are collected and the symbol space beneath them
  deduplicated.
- "The music contains the instrument" becomes literal in DreamOS — what
  the InterBrain video should demonstrate, announcing what was built.
- A slogan: in DreamOS there is no authority, only **co-authority** — we
  co-author the story; the vision evolves as the culture that it attracts
  contributes to it.
